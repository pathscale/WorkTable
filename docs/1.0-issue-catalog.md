# WorkTable 1.0 issue catalog

Audit date: 2026-08-04  
Audited revision: `origin/master` at `17e7b4e`  
GitHub milestone: [1.0.0](https://github.com/pathscale/WorkTable/milestone/3)

## Release recommendation

Do not cut the final 1.0.0 release yet. The public API is already versioned as
`1.0.0-beta.1`, but six open issues are correctness, memory-safety, or durability
gates. Six more issues require either implementation or an explicit compatibility
decision before the API and persistence format are declared stable.

The 1.0 milestone deliberately excludes additive features and internal refactors
that can ship after 1.0 without breaking users.

## 1.0 release blockers

| Issue | Finding | Required outcome |
|---|---|---|
| [#15: tuple primary keys](https://github.com/pathscale/WorkTable/issues/15) | Valid persistence bug. A clean-master probe compiled and inserted a persisted `(u64, u64)` key, but the row was missing after drain and reload. The in-memory tuple test passes. | Persisted insert/reload/select/update/delete/range coverage for tuple keys, including format or migration coverage. |
| [#23: randomly failing tests](https://github.com/pathscale/WorkTable/issues/23) | Valid and reproduced. The integration suite failed twice among 66 audit executions. The captured failure was `worktable::unsized_::update_parallel_more_strings_with_select_unique`, panicking in WorkTablesIndex 0.0.4 with `target was found while the node was locked`. | Fix the WTI invariant violation, publish and pin the fixed version, then complete a high-count clean matrix. |
| [#36: persistence lifecycle](https://github.com/pathscale/WorkTable/issues/36) | Valid. There is no joinable `close`, terminal state, or surfaced engine failure. `wait_for_ops` returns `()`. Apply errors are warnings and later work continues. Busy drop detaches the engine. | `Running -> Closing -> Closed` and terminal `Failed(error)` states; rejected intake; waiter wakeup; `close().await`; root-cause propagation. |
| [#37: lock-free insert versus locked mutations](https://github.com/pathscale/WorkTable/issues/37) | Partially improved, not proved resolved. Churn tests are enabled and passed during the audit, but insert still installs index reachability before unghosting and does not join the row-lock protocol used by update/delete. | Deterministic schedule coverage proving the publish window safe, or one serialization/publication protocol for insert, update, delete, and upsert. |
| [#40: sound row publication by default](https://github.com/pathscale/WorkTable/issues/40) | Newly filed blocker. `docs/versioned-row-publication.md` states that the default path can deserialize archived bytes while a writer mutates them—a Rust data race—and can reuse a physical link while a reader still holds it. The sound prototype is off by default. | A sound default generated API across insert/update/delete/vacuum/reload and all supported indexes. Performance may choose among sound designs, never retain undefined behavior. |
| [#41: durability and crash-recovery contract](https://github.com/pathscale/WorkTable/issues/41) | Newly filed decision blocker. The torn-shutdown test accepts lost or phantom rows after `SIGKILL`; the stronger row-fidelity test is ignored. | Either crash-atomic/recoverable batches, or an explicit best-effort tier with typed corruption, supported rebuild/recovery, and a precise guarantee matrix. Phantom rows cannot be silently accepted. |

## 1.0 hardening and compatibility decisions

These belong in the milestone because changing the answer after 1.0 could break
source syntax, public ownership conventions, or persisted files. A documented
decision may close an item where implementation is intentionally deferred.

| Issue | Status and 1.0 decision |
|---|---|
| [#1: separate column attributes](https://github.com/pathscale/WorkTable/issues/1) | Valid DSL decision. Implement and test the new syntax now, or explicitly freeze inline modifiers as the 1.0 grammar. The parser still carries the original TODO. |
| [#3: project documentation](https://github.com/pathscale/WorkTable/issues/3) | Valid release gate after narrowing. Require compiling README examples, generated API documentation, and explicit concurrency, durability, backend, and persistence limitations. Internal codegen rustdoc completeness is post-1.0 work. |
| [#13: schema in `SpaceInfo`](https://github.com/pathscale/WorkTable/issues/13) | Confirmed open: every `SpaceInfoPage` constructor still writes `row_schema: vec![]`. Populate and version it before format freeze, or declare persisted data typed/opaque and close the CLI-oriented request. |
| [#18: borrowed versus owned public API](https://github.com/pathscale/WorkTable/issues/18) | Valid API audit. Inventory generated methods and compile-test `String`, tuple, and custom keys. Adopt `Borrow`/references where appropriate, or explicitly freeze the owned conversion API. |
| [#31: vacuum disk reclamation](https://github.com/pathscale/WorkTable/issues/31) | Valid. Persisted vacuum is logically correct but neither truncates the data file nor durably reuses freed pages. Implement reclamation/reuse or explicitly document in-memory-only compaction and expose growth metrics. |
| [#35: non-CDC mutations burn event IDs](https://github.com/pathscale/WorkTable/issues/35) | Valid invariant hardening. No currently reproduced persistent path violates it, but the API does not prevent future non-CDC mutations from permanently gapping persistence. Add type-level restriction or at least documentation plus a deterministic tripwire. |

## Audit evidence

- `cargo test --workspace --all-targets` passed once on clean `origin/master`:
  127 library tests, 334 integration tests, 3 ignored integration tests, 64
  codegen tests, and the performance-measurement tests.
- Repeated integration execution was not clean: two failures occurred among 66
  executions. One captured the WorkTablesIndex panic recorded in #23.
- The persisted tuple-key probe inserted and drained successfully but failed
  its post-reload lookup, confirming #15.
- Passing integration runs repeatedly logged `PersistenceTask dropped with work
  in flight`; one run also logged a three-component cancelled batch-apply
  failure while the test still passed. This confirms that test success does not
  currently imply persistence-engine health (#36).
- Three default integration tests remain ignored: concurrent persistence,
  continuous vacuum-manager behavior, and the strong torn-shutdown row-fidelity
  contract. Feature-specific S3 coverage is also ignored.

Local benchmark load affects latency results but does not explain assertion
panics, missing rows after reload, or lifecycle state-machine gaps.

## Active pull request interaction

[PR #39](https://github.com/pathscale/WorkTable/pull/39) adds native Arctic and
Congee persistence and targets a beta release. It is not counted as a GitHub
issue, but it expands the persistence format surface. If it lands before final
1.0, its checkpoint/WAL migration policy and durability boundaries must be
resolved consistently with #13, #36, and #41. Experimental persisted ART
support should remain explicitly beta until those release gates and target
hardware validation are complete.

## 1.0 exit checklist

1. Close all six `release-blocker` issues with regression evidence.
2. Resolve or explicitly accept every `release-hardening`/`needs-decision`
   issue and record the decisions in public documentation.
3. Complete at least 100 consecutive clean default integration-suite runs and
   a separate all-features matrix; no backend assertion panic is acceptable.
4. Triage every ignored correctness test. Keep an ignored test only when it
   documents a clearly published non-guarantee rather than an accidental gap.
5. Run `cargo fmt --all -- --check`, strict workspace/all-target Clippy, full
   tests, documentation build, and `cargo publish --dry-run` from the exact
   proposed release commit.
6. Publish a durability matrix, supported migration policy, known limitations,
   and recovery procedure before tagging 1.0.0.
